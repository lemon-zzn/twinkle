# 眨眼检测算法回测与 bump 研究报告（±0.8s）

- 数据：`sessions/hp_blink_*` 当前 8 个 session。
- 匹配口径：visual blink truth，声学事件在标注前后 `±0.8s` 内一对一匹配。
- 达标条件：召回率 > 0.8，误判率 FP/(TP+FP) < 0.4，且 TP > FP。
- 本轮没有做超参数搜索；改动是新增 `bump` 算法路径，并把周期性触发改为诊断指标。

## 关键结论

1. 声波物理传播延迟通常不是 ±0.8s 的主因；1m 往返约 6ms。主要延迟来自音频缓冲、FMCW chunk、检测窗口关闭、事件峰值/中心时间选择、视觉标注时钟。算法上可通过报告 bump/episode 峰值时间和固定系统偏移校准来减少，但设备缓冲抖动不能完全消除。
2. 前端波形里的 bump 已经可以被算法检测：新增 `bump` 方法用局部峰值 prominence、左右回落、I/Q viewing projection、幅度/相位/运动/空间证据生成事件。
3. 但 bump 单独不是充分条件：8 个 session 汇总 `bump` 召回 0.697，但误判率 0.604，说明很多非眨眼扰动也有 bump。暂不把它接入 `hybridpulse` 实时主路径，只作为独立算法和 features 诊断指标。
4. 周期性误判仍需继续解决：报告里增加了 `fp_cluster_ratio` 和 `twinkle_periodic_clock_suppressed`/`bump_periodic_clock_suppressed` 诊断。直接硬抑制 twinkle 周期链会误伤已知有效的 triangle/hybridpulse 路径，因此本轮只记录诊断，不在主路径硬拦截。

## 本轮代码改动

- 新增 `BumpBlinkDetector`：局部 bump 形态检测，输出 `bump_prominence`、`bump_return_ratio`、`bump_source_diversity` 等诊断。
- CLI/benchmark 支持 `--blink-method bump`。
- 实时 `features.csv` 增加 bump 诊断字段，方便现场比较前端 bump 与算法事件。
- 保守处理：`hybridpulse`/`both` 主路径未采用 bump 作为触发源，避免把高误判 bump 带入实时结果。
